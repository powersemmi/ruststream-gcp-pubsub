# Аренда

Streaming pull берёт каждое сообщение в аренду: клиент продлевает его срок подтверждения, пока
работает обработчик, а управление потоком ограничивает, сколько сообщений клиент держит.

<Diagram name="leases" words={words} />

Streaming pull - это один долгоживущий поток gRPC на подписку. Pub/Sub отправляет по нему
сообщения по мере их поступления, и у каждого есть срок подтверждения. Сообщение, которое до
истечения срока не подтвердили и срок которого не продлили, доставляется снова, возможно другому
подписчику.

Клиентская библиотека отодвигает этот срок. Для каждого сообщения, которое приложение ещё держит,
она отправляет `modifyAckDeadline` и переносит срок не дальше чем на
[`ack_extension`](api:ruststream_gcp_pubsub::GooglePubSub::ack_extension) вперёд (по умолчанию
60 секунд, значение ограничено пределами от 10 до 600). Так она поступает не дольше
[`max_lease`](api:ruststream_gcp_pubsub::GooglePubSub::max_lease), по умолчанию один час. Процесс,
который упал, ничего не продлевает, поэтому его сообщения возвращаются в подписку, как только
истекут их сроки.

Управление потоком работает на уровне потока gRPC. Pub/Sub перестаёт отправлять, пока в потоке
остаются незавершёнными
[`max_outstanding`](api:ruststream_gcp_pubsub::GooglePubSub::max_outstanding)
сообщений (по умолчанию 1000) или 100 МиБ, и продолжает, когда их число падает ниже предела.
Поэтому медленный обработчик замедляет собственный поток, а сообщения, которые он ещё не получил,
ждут в подписке.

ack удаляет сообщение из подписки. nack - это `modifyAckDeadline` с нулевым сроком: сообщение
покидает набор аренд, и Pub/Sub доставляет его снова, как показывает страница
[Повторная доставка](redelivery.md).

Числа взяты из клиента `google-cloud-pubsub` 1.3
([`Subscribe`](https://docs.rs/google-cloud-pubsub/1.3.0/google_cloud_pubsub/builder/subscriber/struct.Subscribe.html))
и у Google ([управление арендой](https://docs.cloud.google.com/pubsub/docs/lease-management)).
