# Путь

Путь одного сообщения Pub/Sub через сервис RustStream: streaming pull, доставка, обработчик, ответ
и ack.

<Diagram name="path" words={words} />

Клиент снимает сообщение с потока и начинает его аренду. Задача перекачки без копирования
оборачивает его в [`PubSubMessage`](api:ruststream_gcp_pubsub::PubSubMessage): данные остаются
буфером клиента, а атрибуты переходят в заголовки. Ключ упорядочивания становится заголовком
`partition-key`, а счётчик попыток - заголовком `pubsub-delivery-attempt`, если у подписки есть
политика dead-letter.

Ответ обработчика кодируется в буфер, который как есть становится данными исходящего сообщения,
потому что клиент оставляет у себя байты, которые публикует. Заголовки становятся атрибутами.
Заголовок не в UTF-8 приводит к ошибке публикации, потому что атрибут - это текст. Ключ, заданный
для публикации, становится ключом упорядочивания сообщения, как показывает страница
[Порядок](pubsub/ordering.md).

Издатель возвращает управление, когда Pub/Sub присвоил сообщению идентификатор. Если ответ не
удалось опубликовать, доставка завершается переобработкой, и сообщение возвращается.

Доставка завершается после ответа. ack уходит со следующим пакетом подтверждений клиента, примерно
через 100 миллисекунд. Чем становится каждый исход, показывает страница [Завершение](settlement.md).
