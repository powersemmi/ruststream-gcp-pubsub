# Пакетная обработка

Это руководство передаёт обработчику много сообщений сразу, для работы, которая дешевле на пакет, чем на сообщение, например одной записи в хранилище данных.

Pub/Sub доставляет сообщения по одному и завершает каждое отдельно.
Сервис сам собирает доставки одной подписки в пакет, вызывает обработчик один раз на пакет, а затем завершает каждое его сообщение.

Пример загружает клики по страницам в аналитическое хранилище.

Параметр-срез `&[Click]` делает `load` [пакетным обработчиком](../components/subscriptions/batches.md).
[`batch_wait`](api:ruststream_gcp_pubsub::GooglePubSub::batch_wait) на дескрипторе - сколько неполный пакет ждёт новых сообщений, здесь полсекунды.
Пакет передаётся, как только заполнится, или по истечении ожидания с тем, что в нём есть.

`load` возвращает по исходу на каждый клик в порядке пакета.
Клик пользователя, которого хранилище ещё не знает, переобрабатывается: Pub/Sub доставляет этот клик снова, и он приходит отдельно или в одном из следующих пакетов.
Клик без страницы отбрасывается, а остальные подтверждаются.
Один `HandlerOutcome` завершает весь пакет одинаково.
В ручной форме `Ok(())` подтверждает пакет, а `Err` содержит исходы для каждого клика.

`batch(nonzero!(100))` задаёт размер пакета, и без него пакетный обработчик не компилируется.
Каждое сообщение пакета остаётся в аренде, пока пакет не завершён, поэтому размер пакета не превышает [`max_outstanding`](../components/subscriptions/max-outstanding.md) подписки, по умолчанию 1000.
Объявление dead-letter считает каждый клик отдельно: после пяти доставок клик уходит в `clicks-dead`, в скольких бы пакетах он ни побывал.
Тему dead-letter описывает руководство [Подтверждение и переобработка](retries.md).

## Тестирование

Тесты публикуют клики вместе через `tokio::join!`, чтобы они попали в один пакет, и читают пакеты через `assert_batch_sizes` и `batches`.
Переобработанный клик виден как пакет из одного сообщения: сначала пакет из двух, затем клик незнакомого пользователя отдельно ещё четыре раза, после чего он оказывается в `clicks-dead`.
Работу с обвязкой описывает руководство [Тестирование сервиса на Pub/Sub](testing.md).
